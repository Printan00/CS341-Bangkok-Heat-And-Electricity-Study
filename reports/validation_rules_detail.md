# ระบบตรวจข้อมูลก่อนใช้งาน (#19) — ฉบับละเอียด

ฉบับสั้น: [`validation_rules.md`](validation_rules.md) · ฉบับนี้มีกฎครบทุกข้อ พร้อมผลกับไฟล์ตัวอย่างจริง

ขั้นตรวจข้อมูล (Validate) ตรวจไฟล์แบบสอบถามก่อนนำไปใช้ แถวที่ผิดจะถูกแยกไปเก็บในโฟลเดอร์ `quarantine/` พร้อมเหตุผล (ไม่ลบทิ้ง)
โค้ดอยู่ที่ `lambdas/validate/` · ค่าที่กฎใช้ (รายชื่อคอลัมน์ ตัวเลือกคำตอบ รายชื่อชุมชน) อยู่ที่ `lambdas/validate/contracts/*.json` · ยังไม่ได้ทดสอบบน AWS

> **แบบสอบถาม 2 ชุด:** Happy Home (สำรวจครัวเรือน ปี 2569) และ SoVI (สำรวจความเปราะบางทางสังคม ปี 2566)
> เอกสารนี้แสดงเฉพาะจำนวนรวม จำนวนที่น้อยกว่า 5 เขียนเป็น `<5` ไม่มีรหัสครัวเรือนหรือตำแหน่งบ้าน

---

## 1. ภาพรวม

```
raw/<แบบสอบถาม>/<รหัสรอบ>/<ไฟล์>.xlsx      ← สคริปต์อัปโหลด scripts/ingest.py (1 รอบ = 1 ไฟล์)
        │
        ▼  ขั้นตรวจข้อมูล (Lambda ชื่อ bhes-validate)
   1) กฎทั้งไฟล์    ไม่ผ่าน → หยุดทั้งไฟล์ และส่งผล valid = false
   2) กฎรายแถว     ไม่ผ่าน → แยกแถวนั้นไปเก็บ / เตือน → แถวผ่าน แต่ติดป้ายเตือน
   3) กฎ B06       แถวที่ถูกแยกเกิน 15% → หยุดทั้งไฟล์
        │
        ▼
quarantine/<แบบสอบถาม>/<รหัสรอบ>/  (รายงาน + แถวที่ถูกแยก + รายชื่อแถวที่ผ่าน)
```

- **ชื่อแบบสอบถามในโฟลเดอร์ (`source`):** `happy_home` หรือ `sovi`
- **รหัสรอบ (`batch_id`):** ชื่อแบบสอบถาม + 12 ตัวแรกของลายนิ้วมือไฟล์ (sha256) ไฟล์เดิมจึงได้รหัสเดิมเสมอ
- **ระบบควบคุมขั้นตอน (Step Functions):** ดูค่า `valid` ถ้าเป็น `false` จะหยุดที่ขั้น `ValidationFailed`
- ขั้นตรวจข้อมูล**ไม่เขียน**โฟลเดอร์ข้อมูลที่พร้อมใช้ (`trusted/`) ขั้นแปลงข้อมูล (Transform, #20) อ่านรายชื่อแถวที่ผ่านจากไฟล์ `manifest.json` (ใช้ได้เมื่อสถานะเป็น `passed`)

## 2. ผลกับไฟล์ตัวอย่างจริง

| แบบสอบถาม | แถวเข้า | ผ่าน | ถูกแยก | ติดป้ายเตือน |
|---|---|---|---|---|
| Happy Home | 88 | 81 | 7 (R03 หาชุมชนไม่เจอ) | 10 |
| SoVI | 500 | 500 | 0 | <5 |

นอกจาก 7 แถวนี้ ข้อมูลสะอาด: รหัสไม่ซ้ำ, ช่องติ๊กตรงกับข้อความคำตอบ, ข้อที่ควรข้ามถูกข้ามจริง, ไม่มีแถวซ้ำ, ตัวแปรที่ใช้วิเคราะห์ไม่มีค่าว่าง

**กฎช่วยคำถามวิจัยใน proposal อย่างไร** (ขั้นตรวจข้อมูลไม่ได้ตอบคำถามเอง แต่ทำให้ข้อมูลที่ใช้ตอบถูกต้อง)

| คำถามวิจัย | ตัวแปรหลัก (เลขข้อในแบบสอบถาม) | ตรวจด้วยกฎ |
|---|---|---|
| ข้อ 1: ลักษณะบ้านสัมพันธ์กับผลกระทบจากความร้อนอย่างไร | วัสดุหลังคา (B4), ฝ้าเพดาน (B6), ฉนวนกันความร้อน (B7), การระบายอากาศ (B8), ร่มเงารอบบ้าน (B9), บ้านร้อนแค่ไหนในหน้าร้อน (C2.1), ผลกระทบต่อรายได้ สุขภาพ ความเครียด (D1–D3) | R04, R05, R07 |
| ข้อ 2: ภาระค่าไฟเทียบรายได้ต่างกันอย่างไร | รายได้ต่อเดือน (A7), ค่าไฟต่อเดือนช่วงปกติ (E1.1) และหน้าร้อน (E1.2), เครื่องใช้ไฟฟ้าที่มี เช่น แอร์ (E2.1) / SoVI: รายได้ รายจ่าย หนี้สิน เงินออม (ข้อ 15–18) | R04, R05, R06, S03, W01, W02, W05 |
| ข้อ 3: ครัวเรือนกลุ่มใดควรได้รับช่วยเหลือก่อน | การใช้ธรรมชาติช่วยลดความร้อน/น้ำท่วม (ส่วน F), การมีส่วนร่วมในชุมชน (ส่วน G), ศูนย์ชุมชน (ส่วน H), การปรับปรุงบ้าน (ส่วน I), คะแนนความเปราะบางของ SoVI | R05, R06, S06 |
| เกณฑ์ความสำเร็จ S1: คุณภาพข้อมูล | หัวคอลัมน์ถูกต้อง, ค่าว่าง, ข้อมูลซ้ำ, ค่าผิดปกติ | B03, จำนวนค่าว่างในรายงาน, R02/S01/W09, W01–W09 |

**ข้อสังเกตสำหรับการวิเคราะห์ (ไม่ใช่กฎ)**
- **แยกผลของความร้อนออกจากน้ำท่วมได้ยาก:** หลายครัวเรือนตอบเหมือนกันทั้งสองภัย เช่น ผลกระทบต่อรายได้ (D1.1) ตอบเหมือนกัน 69/88 แถว ส่วนความขัดแย้งในครอบครัว (D2.3) และกลุ่มที่เดินทางลำบาก (G6) ตอบเหมือนกันครบ 88/88 ไม่ใช่ข้อมูลผิด จึงไม่แยกออก แต่ต้องเขียนเป็นข้อจำกัดของคำถามวิจัยข้อ 1
- **SoVI ไม่มีค่าไฟแยก** มีแค่รายจ่ายรวม (ข้อ 16) ฝั่ง SoVI จึงคำนวณภาระค่าไฟไม่ได้ ใช้ได้แค่ภาระการเงินทั่วไป (ข้อ 15–18)

## 3. ระดับของผลตรวจ

| ระดับ | ผล |
|---|---|
| ไม่ผ่าน (`FAIL`) | กฎทั้งไฟล์ → หยุดทั้งไฟล์ / กฎรายแถว → แยกแถวนั้นไปเก็บ |
| เตือน (`WARN`) | แถวผ่าน แต่ใส่รหัสกฎในคอลัมน์ป้ายเตือน (`dq_flags`) ให้ผู้วิเคราะห์เลือกว่าจะตัดหรือไม่ |

## 4. กฎทั้งไฟล์ (ไม่ผ่าน = หยุดทั้งไฟล์)

| กฎ | ตรวจอะไร | ไฟล์จริง |
|---|---|---|
| **B01** ข้อมูลส่วนตัว | ไม่มีคอลัมน์ที่แท็บบันทึกการทำนิรนาม (`Audit_log`) บอกว่าลบไปแล้ว เช่น ชื่อ บ้านเลขที่ ตำแหน่ง GPS เต็ม (Happy Home 86 / SoVI 30 คอลัมน์) · แท็บการตั้งค่า (`Settings`) ของ Happy Home ต้องบอกว่าปัดตำแหน่งบ้าน (`GPS_MODE=round`) ไม่เกิน 3 ตำแหน่งทศนิยม (`GPS_DECIMALS ≤ 3`) และไม่เก็บข้อความอิสระ (`KEEP_FREE_TEXT=False`) · **ตำแหน่งบ้านในข้อมูลจริง**ต้องมีทศนิยมไม่เกิน 3 ตำแหน่ง (ไม่เชื่อแค่แท็บการตั้งค่า) | ผ่าน |
| **B02** เปิดไฟล์ได้ + แท็บครบ | เป็นไฟล์ Excel (.xlsx) ที่เปิดได้ (ไม่ใช่ไฟล์ CSV ที่เปลี่ยนนามสกุล ไม่ขาด ไม่เสีย) และมีแท็บครบตามตารางด้านล่าง | ผ่าน |
| **B03** หัวคอลัมน์ | ชื่อและลำดับคอลัมน์ตรงกับที่ตกลงไว้ (Happy Home 343, SoVI 384 คอลัมน์) | ผ่าน |
| **B04** จำนวนแถว | ไม่มีแถวเลย → ไม่ผ่าน / จำนวนแถวไม่เท่าที่คาด (Happy Home 88, SoVI 500) → เตือน | ผ่าน |
| **B06** สัดส่วนแถวที่ถูกแยก | แถวที่ถูกแยกเกิน **15%** → ไม่ผ่าน | Happy Home ≈ 8%, SoVI 0% |

- **ถ้าหยุดที่กฎทั้งไฟล์ (รวม B01):** ไม่เก็บแถวใดๆ ไฟล์แถวที่ถูกแยก (`rows.jsonl`) ว่าง และรายชื่อแถวที่ผ่าน (`manifest.json`) มีสถานะ `failed` เพื่อไม่ให้ข้อมูลส่วนตัวไปค้างอยู่ในโฟลเดอร์ที่แยกเก็บ
- **ไฟล์หน้าตาแปลก** (แท็บการตั้งค่าว่าง, ไฟล์เสีย, ไม่ใช่ .xlsx) ได้ผล B01 หรือ B02 พร้อมรายงาน ระบบไม่ล่ม
- **แท็บที่ต้องมีในไฟล์ (B02):** ขาดแท็บไหน = ไม่ผ่าน (ตรวจแค่ว่ามีแท็บชื่อนี้ ไม่ได้อ่านเนื้อหาในแท็บบันทึกการทำนิรนาม)

| แบบสอบถาม | แท็บ | มีไว้ทำอะไร |
|---|---|---|
| Happy Home | `Data` | ข้อมูลหลัก 1 แถว = 1 ครัวเรือน |
| | `Audit_log` | บันทึกการทำนิรนาม (คอลัมน์ไหนถูกลบหรือแปลง) เป็นที่มาของรายชื่อคอลัมน์ต้องห้ามใน B01 |
| | `Settings` | ค่าที่ใช้ตอนทำนิรนาม (ปัดตำแหน่งบ้านกี่ตำแหน่ง ฯลฯ) ที่ B01 ตรวจ |
| SoVI | `ใส่ค่าคะแนน` | ข้อมูลหลัก 1 แถว = 1 ผู้ตอบ (คำตอบ + คะแนน) |
| | `ค่าคะแนน` | เกณฑ์การให้คะแนนแต่ละข้อ |
| | `Audit_log` | บันทึกการทำนิรนาม |

- **ทำไม B03 สำคัญกับ Happy Home:** คอลัมน์ของตารางน้ำท่วม/ความร้อนจับคู่กับคำถามตามตำแหน่ง ถ้าคอลัมน์เลื่อน ความหมายจะผิดทั้งไฟล์โดยไม่มีอะไรแจ้งเตือน
- **ทำไม B06 ใช้ 15%:** Happy Home ถูกแยกอยู่แล้ว 7/88 ถ้าใช้ 10% จะยอมให้ผิดเพิ่มได้แค่ 1 แถว ส่วน 15% ยอมได้ถึง 13/88 และยังจับไฟล์ที่พังจริงได้ (ไฟล์พังมักผิด 30% ขึ้นไป)
