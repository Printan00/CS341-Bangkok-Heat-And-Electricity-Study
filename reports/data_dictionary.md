## 2. คำตอบ 3 ข้อของการ์ด #14

### 2.1 แยกผลจากความร้อนออกจากน้ำท่วมได้ไหม (Happy Home)

**ได้ ในโครงสร้างแบบสอบถาม** (ยืนยันจาก `.docx` และหัวคอลัมน์)
- ส่วน C แยกเป็น C1 น้ำท่วม และ C2 ความร้อน (C2.1–C2.8) คนละชุดคำถาม
- ผลกระทบด้านรายได้ สุขภาพ ความเครียด บริการที่หยุดชะงัก (D1.1–D3.2) และบทบาทตามเพศ/กลุ่ม (G1, G2, G3, G6) เป็นกริด **แยกคอลัมน์ น้ำท่วม กับ ความร้อน** (ชื่อคอลัมน์ `น้ำท่วม`/`ความร้อน` พร้อมเลขต่อท้าย) และข้อที่ตอบได้หลายข้อมี flag 0/1 ต่อภัยแยกกัน
- ข้อที่ปนกัน: `B11` (ปัญหาของบ้าน) มีทั้ง "ร้อนมาก" และ "น้ำขังรอบบ้าน" แต่เป็นตัวเลือกคนละอัน แยกได้; คอลัมน์ที่เป็นข้อความรวมของกริด D1.2/D2.1/D3.1 (เช่น "น้ำท่วม ความร้อน") ต้องใช้คอลัมน์ flag ลูกแทน

**ข้อจำกัดที่ต้องรายงาน**
- ผลกระทบเป็นการรายงานเองและอ้างอิงความจำ ไม่มีการวัดอุณหภูมิในบ้าน
- คำตอบของสองภัยสอดคล้องกันสูง: ในกริด D1.1 มีประมาณ 69/88 ครัวเรือนที่ตอบระดับผลกระทบด้านรายได้เท่ากันทั้งน้ำท่วมและความร้อน (นับเฉพาะเซลล์ที่ n ≥ 5) จึงแยกผลของความร้อนจากน้ำท่วมได้ยากในเชิงสถิติ ควรรายงานคู่กันหรือควบคุมตัวแปรน้ำท่วม
- ตัวแปรผลหลักที่มีความแปรผันพอ: **D1.1 ความร้อน** (มาก 21 / บางส่วน 37 / ไม่กระทบ 29 / ไม่แน่ใจ <5) ส่วน `C2.1` "บ้านร้อนเพียงใด" ตอบ "ร้อนมากทุกวัน" **68/88 (77%)** จึงแทบไม่มีความแปรผัน ไม่เหมาะเป็นตัวแปรผล

### 2.2 SoVI แยกค่าไฟออกจากรายจ่ายรวมได้ไหม

**ไม่ได้ เพราะ SoVI ไม่มีข้อมูลค่าไฟ**
- ค้นหัวคอลัมน์ทั้ง 384 คอลัมน์: ไม่มีค่าไฟรายเดือน ไม่มีเครื่องใช้ไฟฟ้า ไม่มีเครื่องปรับอากาศ ไม่มีตัวแปรความร้อน/อุณหภูมิ
- มีเพียง 4 คอลัมน์ที่เกี่ยวกับไฟฟ้า และเป็นเรื่อง **ไฟฟ้าขัดข้องช่วงน้ำท่วม** กับ **ระยะเวลาการไฟฟ้าแก้ไข** (ข้อ 50, 51, 58) ไม่ใช่ค่าใช้จ่าย
- รายจ่าย (ข้อ 16 `รายจ่ายรวม (ต่อเดือน)`) เป็นยอดรวมแบบช่วงเดียว ไม่แยกหมวด
- ภัยที่ SoVI ครอบคลุมคือ **น้ำท่วมและภัยแล้ง/ขาดแคลนน้ำ** ไม่ใช่ความร้อน

**ผลต่อโครงการ:** Q1 (ความร้อน) และ Q2 (ภาระค่าไฟ) ตอบได้จาก **Happy Home ชุดเดียว (n=88)** SoVI ใช้เป็นบริบท (รายได้ รายจ่าย ลักษณะบ้าน ความสามารถในการปรับตัว) ของ Q3 และเปรียบเทียบระดับกลุ่มเท่านั้น

### 2.3 หน่วยเวลาของค่าไฟกับรายได้ตรงกันไหม

**ตรงกัน (รายเดือนทั้งหมด) แต่เป็นช่วง (band) ไม่ใช่ตัวเลข**

| ตัวแปร (Happy Home) | หน่วย | ชั้น (bands) |
|---|---|---|
| A7 รายได้เฉลี่ยต่อเดือน | บาท/เดือน | <5,000 · 5,001–10,000 · 10,001–20,000 · 20,001–50,000 · >50,000 |
| A8 ค่าใช้จ่ายเฉลี่ยต่อเดือน | บาท/เดือน | ชุดเดียวกับ A7 |
| E1.1 ค่าไฟ **ช่วงปกติ** | บาท/เดือน | <500 · 500–1,000 · 1,001–2,000 · 2,001–3,000 · >3,000 |
| E1.2 ค่าไฟ **ช่วงหน้าร้อน** | บาท/เดือน | ชุดเดียวกับ E1.1 |

**ผลกระทบ:** คำนวณ "ภาระค่าไฟ = ค่าไฟ/รายได้" เป็นค่าเดียวไม่ได้ ควรรายงานเป็น
1. **ช่วงต่ำสุด–สูงสุด** (ค่าไฟต่ำสุด ÷ รายได้สูงสุด ถึง ค่าไฟสูงสุด ÷ รายได้ต่ำสุดของชั้น) โดย 4 ชั้นปลาย (<500, >3,000, <5,000, >50,000) เปิดปลาย ต้องกำหนดเพดาน/พื้นเป็นสมมติฐานและระบุชัด
2. หรือเทียบเชิงอันดับ (ordinal) ระหว่างกลุ่มรายได้กับชั้นค่าไฟ
ทั้งสองแบบต้องเขียนเป็นสมมติฐานของการวิเคราะห์ (ต้องตัดสินใจร่วมกันในทีม, การ์ด #24)

**SoVI เทียบตรงๆ ไม่ได้:** รายได้ SoVI แบ่ง 4 ชั้น (<15,000 · 15,000–30,000 · 30,000–50,000 · 50,000–100,000) ขอบชั้นต่างจาก Happy Home จุดที่ตรงกันมีแค่ 50,000 และ 92% ของ SoVI อยู่ในสองชั้นกลาง

## 5. ข้อเสนอสำหรับ pipeline และการตัดสินใจ (ต่อ #19, #20, #23, #24)

1. **กฎ validation (#19):** id ไม่ซ้ำ; ชื่อชุมชน → normalise เป็น 2 ค่า ไม่ได้ไป quarantine; พิกัดอยู่ใน bounding box กรุงเทพฯ; ค่าไฟหน้าร้อน ≥ ปกติ; รายได้ชั้นต่ำสุดร่วมกับค่าไฟ >3,000 → ธงเตือน (ไม่ลบ); ค่าตอบอยู่ในชุดค่าตามแบบสอบถาม; flag 0/1 ของข้อหลายคำตอบสอดคล้องกัน
2. **Transform (#20):** ทิ้งหรือแยกพิกัดออกจาก Trusted ที่แชร์; คงรหัสนามแฝงเดิม; แปลง band เป็น ordinal + ขอบล่าง/บน
3. **Integration (#23):** ไม่ join SoVI กับ Happy Home ที่ระดับครัวเรือน (ต่างปี ต่างพื้นที่ ต่างขอบช่วงรายได้ และ SoVI ไม่มีค่าไฟ); GEE ทำได้ที่ระดับชุมชนและต้องถามรหัสพื้นที่ SoVI
4. **Q2 วิเคราะห์เป็นช่วง** (ข้อ 2.3) และรายงาน n กับกลุ่มเล็ก (<5) ตามกฎ
5. **ข้อเสนอแก้ Proposal:** แก้ n ≈ 81 → 88; ระบุว่า Q1/Q2 ใช้ Happy Home ชุดเดียว; Decision 1 (GEE เสริม SoVI) ควรเปลี่ยนเหตุผลเป็น "SoVI ไม่มีตัวแปรความร้อนและค่าไฟ" ซึ่งยืนยันด้วยข้อมูลแล้ว

## 6. ข้อจำกัดของรายงานนี้

- ตรวจจากข้อมูลที่ anonymize แล้วเท่านั้น ไม่ได้ยืนยันกับผู้เก็บข้อมูล
- การจับคู่คอลัมน์กริดกับคำถามอิงลำดับใน `.docx` (ตรวจแล้วตรงกันทั้งช่วง D1.1–D3.2 และ G1–G6 แต่ควรให้คนในทีมอีกคนตรวจซ้ำ)
- ชนิดข้อมูล (`kind`) ในไฟล์ CSV เป็นการอนุมานอัตโนมัติ (ไม่ใช่ metadata จริงจากเครื่องมือสำรวจ)
- รายการ "ค่าไฟ/พลังงาน/ความร้อนใน SoVI" มาจากการค้นข้อความหัวคอลัมน์ ถ้าชื่อไม่ตรงคำค้นอาจพลาด (ตรวจร่วมกับชีต `ค่าคะแนน` แล้วไม่พบเพิ่ม)
- ตารางไขว้เชิงสำรวจทำแล้วแต่ **ไม่รายงานตัวเลขรายเซลล์** เพราะ n เล็กและ k-anonymity ไม่ผ่าน
