# Validation + Quarantine Rules (#19)

ขั้น Validate ตรวจไฟล์สำรวจก่อนนำไปใช้ แถวที่ผิดถูกแยกไป `quarantine/` พร้อมเหตุผล (ไม่ลบทิ้ง)
โค้ด: `lambdas/validate/` · ข้อมูลอ้างอิงของกฎ: `lambdas/validate/contracts/*.json` · ยังไม่ได้ทดสอบบน AWS

> **HH** = Happy Home · **SoVI** = SoVI V8 · เอกสารนี้แสดงเฉพาะจำนวนรวม จำนวนที่น้อยกว่า 5 เขียนเป็น `<5` ไม่มีรหัสครัวเรือนหรือพิกัด

---

## 1. ภาพรวม

```
raw/<source>/<batch_id>/<ไฟล์>.xlsx      ← scripts/ingest.py (1 batch = 1 ไฟล์)
        │
        ▼  Lambda bhes-validate
   1) กฎ Batch   ไม่ผ่าน → หยุด batch, valid = false
   2) กฎ Row     FAIL → แถวไป quarantine / WARN → แถวผ่าน แต่ติดธง dq_flags
   3) B06        แถวถูกกักเกิน 15% → หยุด batch
        │
        ▼
quarantine/<source>/<batch_id>/  (รายงาน + แถวที่ถูกกัก + รายชื่อแถวที่ผ่าน)
```

- `source` = `happy_home` หรือ `sovi` · `batch_id` = `<source>-<sha256 12 ตัวแรก>`
- Step Functions เช็ก `valid` ถ้าเป็น `false` จะหยุดที่ `ValidationFailed`
- Validate **ไม่เขียน `trusted/`** ขั้น Transform (#20) อ่านรายชื่อแถวที่ผ่านจาก `manifest.json` (ใช้ได้เมื่อ `status` = `passed`)

## 2. ผลกับไฟล์ sample

| ชุดข้อมูล | แถวเข้า | ผ่าน | ถูกกัก | ติดธงเตือน |
|---|---|---|---|---|
| Happy Home | 88 | 81 | 7 (R03 หาชุมชนไม่เจอ) | 10 |
| SoVI V8 | 500 | 500 | 0 | <5 |

นอกจาก 7 แถวนี้ ข้อมูลสะอาด: รหัสไม่ซ้ำ, flag ตรงกับข้อความ, skip logic ถูก, ไม่มีแถวซ้ำ, ตัวแปรวิเคราะห์ไม่มีค่าว่าง

**กฎรองรับคำถามใน proposal อย่างไร** (Validate ไม่ตอบคำถามเอง แต่คัดให้ตัวแปรที่ใช้ตอบถูกต้อง)

| คำถาม | ตัวแปรหลัก | ตรวจด้วย |
|---|---|---|
| Q1 ลักษณะบ้าน → ผลกระทบจากความร้อน | หลังคา B4, ฝ้า B6, ฉนวน B7, ระบายอากาศ B8, ร่มเงา B9, บ้านร้อน C2.1, ผลกระทบ D1–D3 | R04, R05, R07 |
| Q2 ภาระค่าไฟเทียบรายได้ | รายได้ A7, ค่าไฟ E1.1/E1.2 (รายเดือนทั้งคู่), แอร์ E2.1 / SoVI ข้อ 15–18 | R04, R05, R06, S03, W01, W02, W05 |
| Q3 ใครควรได้รับช่วยเหลือก่อน | NbS (F), การมีส่วนร่วม (G), ศูนย์ชุมชน (H), การปรับปรุงบ้าน (I), คะแนน SoVI | R05, R06, S06 |
| S1 คุณภาพข้อมูล | schema, ค่าว่าง, ข้อมูลซ้ำ, ค่าผิดปกติ, รันซ้ำได้ | B03, `missing_in_passed_rows`, R02/S01/W09, W01–W09, §7 |

**ข้อสังเกตสำหรับการวิเคราะห์ (ไม่ใช่กฎ)**
- **แยกผลความร้อนออกจากน้ำท่วมได้ยาก:** หลายครัวเรือนตอบเหมือนกันทั้งสองภัย เช่น D1.1 ผลกระทบต่อรายได้ ตอบเหมือนกัน 69/88 แถว และ D2.3, G6 ตอบเหมือนกันครบ 88/88 ไม่ใช่ข้อมูลผิด จึงไม่กัก แต่ต้องเขียนเป็นข้อจำกัดของ Q1
- **SoVI ไม่มีค่าไฟแยก** มีแค่รายจ่ายรวม (ข้อ 16) ฝั่ง SoVI จึงคำนวณภาระค่าไฟไม่ได้ ใช้ได้แค่ภาระการเงินทั่วไป (ข้อ 15–18)

## 4. กฎ Batch (ตรวจทั้งไฟล์ ไม่ผ่าน = หยุด)

| กฎ | ตรวจอะไร | sample |
|---|---|---|
| **B01** ความเป็นส่วนตัว | ไม่มีคอลัมน์ที่ `Audit_log` บอกว่าลบแล้ว (ชื่อ, บ้านเลขที่, GPS ดิบ ฯลฯ HH 86 / SoVI 30 คอลัมน์) และ HH แท็บ `Settings`: `GPS_MODE=round`, `GPS_DECIMALS ≤ 3`, `KEEP_FREE_TEXT=False` และ**พิกัดในข้อมูลจริง**มีทศนิยมไม่เกิน 3 ตำแหน่ง (ไม่เชื่อแค่ `Settings`) | ผ่าน |
| **B02** เปิดไฟล์ได้ + แท็บครบ | เป็น .xlsx ที่เปิดได้ (ไม่ใช่ CSV เปลี่ยนนามสกุล, ไม่ขาด, ไม่เสีย) และมีแท็บ (ชีต) ครบตามตารางด้านล่าง | ผ่าน |
| **B03** หัวคอลัมน์ | ชื่อและลำดับตรงกับ contract (HH 343, SoVI 384 คอลัมน์) | ผ่าน |
| **B04** จำนวนแถว | 0 แถว → FAIL / ไม่เท่ากับที่คาด (HH 88, SoVI 500) → WARN | ผ่าน |
| **B06** สัดส่วนแถวเสีย | แถวที่ถูกกักเกิน **15%** → FAIL | HH ≈ 8%, SoVI 0% |

- **หยุดที่กฎ Batch (รวม B01):** ไม่เก็บแถวใดๆ (`rows.jsonl` ว่าง, `manifest.json` เป็น `failed`) เพื่อไม่ให้ข้อมูลส่วนบุคคลไปอยู่ใน quarantine
- **ไฟล์รูปแบบแปลก** (แท็บ `Settings` ว่าง, ไฟล์เสีย, ไม่ใช่ .xlsx) ได้ B01/B02 พร้อมรายงาน ไม่ใช่ Lambda error
- **แท็บที่ต้องมีในไฟล์ (B02)** ขาดแท็บไหน = ไม่ผ่าน (ตรวจแค่ว่ามีแท็บชื่อนี้ ไม่ได้อ่านเนื้อหาของ `Audit_log`)

| ไฟล์ | แท็บ | มีไว้ทำอะไร |
|---|---|---|
| Happy Home | `Data` | ข้อมูลหลัก 1 แถว = 1 ครัวเรือน |
| | `Audit_log` | บันทึกการทำนิรนาม (คอลัมน์ไหนถูกลบ/แปลง) ที่มาของรายชื่อคอลัมน์ต้องห้ามใน B01 |
| | `Settings` | ค่าการทำนิรนาม (ปัดพิกัดกี่ตำแหน่ง ฯลฯ) ที่ B01 ตรวจ |
| SoVI | `ใส่ค่าคะแนน` | ข้อมูลหลัก 1 แถว = 1 ผู้ตอบ (คำตอบ + คะแนน `v…`) |
| | `ค่าคะแนน` | เกณฑ์การให้คะแนนแต่ละข้อ |
| | `Audit_log` | บันทึกการทำนิรนาม |

- **B03 สำคัญกับ HH:** คอลัมน์กริดจับคู่กับคำถามตามตำแหน่ง ถ้าคอลัมน์เลื่อน ความหมายผิดทั้งไฟล์โดยไม่มี error
- **B06 ทำไม 15%:** HH ถูกกักอยู่แล้ว 7/88 ที่ 10% จะยอมเสียเพิ่มได้แค่ 1 แถว ส่วน 15% ยอมถึง 13/88 และยังจับไฟล์ที่พังจริงได้ (มักเสีย 30% ขึ้นไป)

## 7. Output: `quarantine/<source>/<batch_id>/`

| ไฟล์ | มีอะไร | ใครใช้ |
|---|---|---|
| `dq_report.json` | ผ่าน/ถูกกักกี่แถว เพราะกฎไหน และ `missing_in_passed_rows` = ค่าว่างของตัวแปร Q1–Q3 ในแถวที่ผ่าน (HH 24, SoVI 5 ตัว ตาม `report_missing` ใน contract) จำนวนรวมเท่านั้น ไม่มีรหัส | ทีม / รายงาน |
| `violations.csv` | 1 บรรทัดต่อ 1 กฎที่ผิด: rule_id, รหัส, แถวใน Excel, คอลัมน์ | คนแก้ข้อมูล |
| `rows.jsonl` | แถวดิบที่ถูกกัก + rule_ids (**มีพิกัด** สิทธิ์ต้องจำกัดเท่า `raw/`) | คนแก้ข้อมูล |
| `manifest.json` | `status` (`passed`/`failed`) + รหัสที่ผ่าน + `dq_flags` + `community_key` และรหัสที่ถูกกัก | Transform (#20) |

- **เขียนครบทั้ง 4 ไฟล์ทุกครั้ง** รันซ้ำจึงไม่มีไฟล์เก่าจากรอบก่อนค้าง (Lambda ไม่มีสิทธิ์ลบ จึงเขียนทับ)
- ถ้าหยุดที่กฎ Batch: `manifest.json` เป็น `failed` ไม่มีรหัส, `rows.jsonl` ว่าง, `violations.csv` มีแค่กฎ Batch

## 8. สิ่งที่ตัดสินใจแล้ว (2026-11-11)

| เรื่อง | ตัดสินใจ | เพราะ |
|---|---|---|
| 7 แถว HH ที่หาชุมชนไม่เจอ | **กักไว้** ไม่นำไปวิเคราะห์ เขียนเป็นข้อจำกัดในรายงาน | ชื่อชุมชนเป็นตัวอักษรตัวเดียว แต่ทั้ง 7 แถวตอบ B13 (เฉพาะมิตรประชา) จึงน่าจะเป็นชุมชนที่ 3 มิตรประชา 7 ครัวเรือนน้อยเกินไปที่จะเทียบ และ 88 − 7 = 81 ตรงกับตัวเลขที่ประกาศ |
| คะแนน 0 ใน SoVI | **ไม่ใช่ "ข้ามข้อ"** รับค่า 0 ตามเดิม | 0 มีเฉพาะข้อน้ำท่วม: ข้อ 50/51 = ไม่มีปัญหาด้านนั้น / ข้อ 34.3, 34.5 = ชุมชนไม่เคยน้ำท่วม |
| เลข `(NN)` หน้าชื่อชุมชน SoVI | **เก็บเป็นป้าย** ใน `community_code` เชื่อมข้อมูลด้วยชื่อชุมชน (`community_key`) | ไม่รู้ความหมาย และมีแค่ 8 จาก 17 ชุมชน |
| รหัสซ้ำข้าม batch (R02) | **ไม่ตรวจ** ตรวจเฉพาะในไฟล์เดียวกัน | ไฟล์ที่แก้แล้ว ingest ใหม่มีรหัสชุดเดิม ถ้าตรวจข้าม batch จะถูกกักทั้งไฟล์ |
| คำตอบ → คะแนน SoVI (C02) | **ไม่ตรวจ** ใช้คะแนนตามไฟล์ เขียนเป็นข้อจำกัดในรายงาน | เกณฑ์ในชีต `ค่าคะแนน` เป็นข้อความอิสระ ต้องจับคู่เองทั้ง 126 คอลัมน์ ไม่คุ้มกับไฟล์ที่ได้มาครั้งเดียว |

| E1.3 ตอบว่าค่าไฟ "เพิ่ม" แต่ช่วง E1.1 = E1.2 (53 แถว) | ช่วงค่าไฟกว้าง ค่าไฟเพิ่มจริงแต่ยังอยู่ช่วงเดิมได้ |

## 11. ช่องโหว่ที่รู้แล้ว / ยังไม่ได้ทำ

- ยังไม่มี `rule_version` ใน output
- ยังไม่ได้ทดสอบบน AWS จริง (`terraform apply` → ingest → `start-execution`)
- **ความเสี่ยงต่ำ (บันทึกไว้ ยังไม่แก้)**
  - SoVI: ความเป็นส่วนตัวพึ่งการทำนิรนามต้นทาง ไม่มีแท็บ `Settings` ให้ตรวจ คอลัมน์เกินจับได้ด้วย B03 แต่ไม่ได้สแกนข้อความในช่องคำตอบ
  - `dq_report.json` แสดงยอดรวมแถวที่ถูกกัก/ติดธงโดยไม่ปัดเป็น `<5` (ยอดรายกฎปัดแล้ว)
  - ถ้ารันเทสต์ในเครื่องแล้ว `terraform apply` โฟลเดอร์ `__pycache__` จะถูก zip เข้า Lambda ด้วย (`.gitignore` ไม่มีผลกับการ zip) ไม่อันตราย ลบก่อน apply ได้
  - ขั้น Validate ใน Step Functions ไม่มี Retry ถ้า S3 ขัดข้องชั่วคราว execution จะล้ม ให้รันใหม่
  - `violations.csv` นับเลขแถวตามลำดับที่อ่าน ถ้า Excel ข้ามแถวว่างกลางไฟล์ เลขแถวอาจคลาดจาก Excel

## 12. คำถามที่ยังเปิด

- แถวที่ติด W01 (7 แถว) จะตัดออกจากการวิเคราะห์ Q2 หรือรายงานทั้งแบบมีและไม่มี
- **ถ้ามีข้อมูลสำรวจเพิ่ม:** Transform ใช้ batch ล่าสุดแทนของเดิม ถ้า batch ใหม่มีแค่ครัวเรือนที่เพิ่มมา ข้อมูลเดิมจะหาย ทางเลือก A: ตกลงว่าต้อง export ไฟล์รวมทั้งหมดทุกครั้ง (แนะนำ) / B: Transform รวมทุก batch ต่อกัน (ต้องกลับมาตรวจรหัสซ้ำข้าม batch)
- ข้อมูลเพิ่มที่สำรวจนอกช่วง 2026-06 ถึง 2026-08 หรือมีชุมชนใหม่ ต้องแก้ `month_min`/`month_max` และ `community_map` ใน contract ก่อนรัน ไม่อย่างนั้นแถวจะถูกกักเกิน 15%

## 13. วิธีแก้กฎ / ปล่อยแถวออกจาก quarantine

- **ห้ามแก้แถวด้วยมือ** แก้ที่ contract (เช่น เพิ่มป้ายชุมชนใน `community_map`) แล้วรัน pipeline ของ batch นั้นใหม่

- ก่อนเทียบค่า ระบบตัดช่องว่างและถือว่า `-` กับ `–` เหมือนกันเท่านั้น ไม่แปลงความหมายข้อมูล
